## ⭐ Активный формат — `H` (Премиум-энциклопедия в стиле BC.Game)

**Все новые проекты создаются только в формате `H`.** Старые форматы A-G законсервированы.

После анализа конкурента [bc-game-brazil.com](https://bc-game-brazil.com/) принято решение: длинные энциклопедические страницы с большим объёмом текста (~3500 слов на главной), многочисленными изображениями (15-20 заглушек) и повторяющимися промо-баннерами с бонусом дают лучшее SEO-покрытие, удержание и конверсии партнёрской ссылки.

### Ключевые отличия формата H от старых

| Параметр                                    | Раньше (A-G)                        | Сейчас (H)                                                  |
| ------------------------------------------- | ----------------------------------- | ----------------------------------------------------------- |
| Объём главной                               | 600-2000 слов                       | **3000-4000 слов**                                          |
| Объём подстраниц                            | 300-1200 слов                       | **1500-2500 слов**                                          |
| Объём слот-обзоров                          | 400-700 слов                        | **1200-1800 слов**                                          |
| Изображения на главной                      | 5-8 заглушек                        | **15-20 заглушек**                                          |
| Изображения на подстраницах                 | 3-5 заглушек                        | **8-12 заглушек**                                           |
| Промо-баннеры с бонусом                     | 1-2 раза                            | **5-7 повторов**                                            |
| Минимум H2-секций на главной                | 7                                   | **12-15**                                                   |
| Тон                                         | Личный (1-е лицо) или корпоративный | **3-е лицо платформы + обращение «вы»**                     |
| Персона автора                              | Опционально                         | **Нет** (без ArticleMeta с именем, без /about с биографией) |
| Сводная таблица параметров                  | —                                   | **Обязательна** (с эмодзи-маркерами в Hero)                 |
| Таблица VIP-уровней / бонусов на 4 депозита | —                                   | **Обязательна** где-то на главной                           |

Подробное описание формата H — в `docs/VARIATION_STRATEGY.md` (секция 12) и `docs/CONTENT_GUIDE.md`.

## 0. Конфигурация проекта (JSON)

Перед генерацией каждого нового сайта агенту передаётся конфиг. Все параметры обязательны.

Поле `region` — код страны (KZ, UZ, AZ, KG, TJ, BY, UA, RU). Определяет автоматически: валюту, банки, города, спорт-лиги, имена, провайдеры, документы, SEO geo-мета. Полный справочник — `docs/REGIONS.md`.

Поле `content_format` — всегда `"H"` для новых проектов (формат «Премиум-энциклопедия» в стиле BC.Game). Поле `author` для формата H не используется (нет персоны автора).

Поле `visual_style` — рекомендованный стиль `"premium-encyclopedia"`. Допустимы также `casino-glam` и `dark-premium` для совместимости.

> **⚠️ Все внешние ссылки — заглушка `#` пока не получены реальные.** При создании проекта `affiliate_url` в конфиге всегда `"#"`, и в коде все CTA-кнопки/ссылки на партнёрский ресурс ведут на `#`. Реальные ссылки подставляются позже на этапе деплоя через find-replace по всем файлам. Подробности — в секции 6, блок «Внешние ссылки».

	"region": "KZ",

## 2. Технический стек

### Обязательно

- **Astro** (последняя стабильная версия) — Static Site Generation, минимум JS на клиенте
- **Tailwind CSS 4** — утилитарная стилизация
- **Node.js 22+** — для сборки
- Сборка < 2 секунд
- Итоговый HTML сжат (`compressHTML: true`)
- Prefetch всех страниц для мгновенных переходов

### Интеграции Astro

- `@astrojs/sitemap` — автоматическая генерация sitemap
- `@tailwindcss/vite` — Tailwind через Vite-плагин

### Производительность

- Google PageSpeed Insights: целевой показатель **95+** (Mobile и Desktop)
- Все изображения из `src/assets/` — Astro автоматически конвертирует в WebP и сжимает
- Шрифты: preload + async загрузка через `media="print" onload="this.media='all'"`
- Один CSS-файл на выходе
- Zero JavaScript runtime (кроме мобильного меню и аккордеона FAQ)

## 5. SEO — максимальная оптимизация под Google

### На каждой странице (обязательно)

- Уникальный `<title>` (до 60 символов, ключевое слово ближе к началу)
- Уникальный `<meta description>` (до 160 символов, call-to-action, не шаблонный)
- `<link rel="canonical">` на себя
- `<meta name="robots" content="index, follow, max-snippet:-1, max-image-preview:large">`
- Open Graph: `og:title`, `og:description`, `og:image`, `og:url`, `og:locale`
- Twitter Card: `summary_large_image`
- Гео-мета: `geo.region: KZ`, `geo.placename: Kazakhstan`
- `<html lang="ru">`, `content-language: ru`
- `theme-color` подстроенный под цветовую схему проекта

### Schema.org разметка

| Страница                   | Тип schema                                                                    |
| -------------------------- | ----------------------------------------------------------------------------- |
| Главная                    | `WebSite` + `SearchAction`                                                    |
| FAQ-секция                 | `FAQPage` с `Question` + `Answer`                                             |
| Подстраницы с инструкциями | `HowTo` + `HowToStep`                                                         |
| Обзоры слотов              | `Review` + `SoftwareApplication` (с `applicationCategory: "GameApplication"`) |
| Все подстраницы            | `Article` с `datePublished`, `dateModified`, `author` (Person)                |
| Хлебные крошки             | `BreadcrumbList`                                                              |
| Страница "О проекте"       | `AboutPage` + `Person`                                                        |

### Внутренняя перелинковка (критически важно для SEO)

Перелинковка — один из главных факторов ранжирования. Правила:

- **Главная**: 5-8 внутренних ссылок (через секции — каждая секция ведёт на релевантную подстраницу)
- **Подстраницы**: 3-5 внутренних ссылок в тексте (НЕ в навигации)
- **Слот-обзоры**: 2-3 ссылки (на /casino + на другие слоты)
- Ссылки **вплетены в текст органично** — как будто автор упоминает тему по ходу рассказа
- Анкоры (текст ссылок) **разнообразные**, содержат ключевые слова, не «нажмите сюда»
- Каждая страница имеет минимум 2 **входящих** ссылки с других страниц
- Ключевые страницы (регистрация, бонусы, казино) получают **больше** входящих ссылок
- Подробные правила перелинковки — в `docs/CONTENT_GUIDE.md`

### Ключевые слова — карта по типам страниц

Для каждого типа страницы определён шаблон ключевых слов. Агент подставляет бренд и название региона из конфига (см. `docs/REGIONS.md`).

| Тип страницы    | Primary keyword                 | Secondary / LSI keywords                                                      |
| --------------- | ------------------------------- | ----------------------------------------------------------------------------- |
| Главная         | `{brand} {регион}`              | `{brand} {код_региона}`, `{brand} 2026`, ставки {регион}, онлайн казино {код} |
| Регистрация     | `{brand} регистрация`           | создать аккаунт, счёт в {валюта}, {код_валюты}                                |

| Зеркало         | `{brand} зеркало`               | рабочее зеркало, альтернативный вход, доступ                                  |

Где `{регион}` = название страны, `{код}` = двухбуквенный код, `{валюта}` = название валюты, `{банк_региона}` = главный банк, `{лига_региона}` = футбольная лига — всё из `docs/REGIONS.md`.

### Формулы title (чередовать между страницами и проектами)

**Формула 1:** `{Primary KW} — {выгода} | {год}`

> `1xBet Регистрация — аккаунт в {валюта} за 2 минуты | 2026`

**Формула 2:** `{Primary KW}: {конкретика + цифра}`

> `1xBet Бонус: до {сумма_бонуса} + 150 фриспинов для новых игроков`

**Формула 3:** `{Действие} {brand} {регион} — {дополнение}`

> `Скачать 1xBet {Регион} — APK для Android без Google Play`

**Формула 4:** `{Вопрос}? {brand} {год}`

> `Как зайти на 1xBet? Рабочее зеркало для Казахстана 2026`

Не использовать одну формулу на всех страницах одного проекта — чередовать.

### Формулы description

- Первые 60 символов — самое важное (Google обрезает на мобильных)
- Включить primary keyword + 1 secondary keyword естественно
- Обязательно call-to-action или конкретная выгода
- Конкретные цифры: сумма бонуса, количество игр, RTP, минимальный депозит
- Не дублировать title дословно — перефразировать

### Плотность ключевых слов на странице

| Тип keyword        | Частота на страницу | Где размещать                                     |
| ------------------ | ------------------- | ------------------------------------------------- |
| Primary keyword    | 3-5 раз             | H1, первый абзац, середина текста, финальный CTA  |
| Secondary keywords | по 1-2 раза каждый  | H2 подзаголовки, alt-теги, анкоры ссылок          |
| LSI / синонимы     | свободно            | по всему тексту для естественности                |
| Название бренда    | max 2 раза на абзац | чередовать с синонимами (платформа, контора, тут) |

### On-page SEO — карта размещения ключевых слов

| Элемент                  | Какой keyword                 | Правило                                         |
| ------------------------ | ----------------------------- | ----------------------------------------------- |
| `<title>`                | Primary                       | Ближе к началу, до 60 символов                  |
| `<meta description>`     | Primary + 1 secondary         | Естественно вплетены, до 160 символов           |
| `<h1>`                   | Primary (переформулированный) | НЕ дублировать title дословно                   |
| Первые 100 слов текста   | Primary                       | В первом-втором предложении                     |
| `<h2>` подзаголовки      | Secondary (по 1 на H2)        | Не в каждом H2, а в 60-70%                      |
| alt-теги изображений     | Secondary/LSI                 | Только 1-2 из всех картинок на странице, не все |
| Анкоры внутренних ссылок | Secondary                     | Разнообразные, описательные                     |
| URL slug                 | Primary (транслит)            | Короткий, без стоп-слов                         |

### Чего НЕ делать (переоптимизация)

- НЕ вставлять keyword в каждый H2 — это спам
- НЕ дублировать title и H1 слово-в-слово — Google понижает
- НЕ писать keyword в alt-тегах ВСЕХ изображений — достаточно 1-2
- НЕ повторять primary keyword больше 5 раз на странице
- НЕ использовать keyword в каждом предложении первого абзаца

### Техническое SEO

- Семантическая HTML-разметка: один `<h1>` на страницу, иерархия h2 → h3 → h4
- Время до первого байта (TTFB) < 200ms (статика)
- Cumulative Layout Shift (CLS) < 0.1
- Largest Contentful Paint (LCP) < 2.5s
- Размер HTML-страницы < 100KB (без ассетов)

### Файлы

- `robots.txt` — Allow: /, Disallow: /api/, ссылка на sitemap (при `noindex: true` — `Disallow: /`)
- `sitemap-index.xml` — автогенерация через @astrojs/sitemap
- `favicon.svg` — SVG для чёткости на любом экране, уникальный для каждого проекта
- `og-default.png` — OG-image по умолчанию (1200×630), уникальный
- `.htaccess` — серверная оптимизация для Apache (см. секцию 13)

## 6. Контент — правила написания текстов (формат H)

### Главный принцип

Текст должен быть **неотличим от написанного реальным редактором/копирайтером**. Ни один AI-детектор (GPTZero, Originality.ai, Turnitin) не должен распознать его как сгенерированный.

В формате H это **подробный энциклопедический обзор онлайн-казино/беттинг-площадки** в духе bc-game-brazil.com. Главная — 3000-4000 слов, 12-15 H2-секций, 15-20 заглушек изображений, повторяющиеся промо-баннеры с бонусом (5-7 раз).

### Категорически запрещено

- Шаблонные AI-обороты: «В данной статье мы рассмотрим...», «В заключение хотелось бы отметить...», «Давайте разберёмся...», «Стоит отметить, что...», «Важно понимать, что...»
- 1-е лицо (это формат A, законсервирован): «я проверял», «лично мне», «по-моему», «закинул 5000 тенге»
- Разговорные вставки (это формат A): «ну», «короче», «ладно», «блин», «вот честно»
- Безупречные оценки без минусов (Google расценивает как заказной контент)
- Повторяющиеся тексты CTA-кнопок в основном тексте (CTA-баннер допускает повтор шаблона, но заголовок каждый раз разный)
- Копипаст текстов между проектами или с внешних сайтов
- Перечислительная структура без связного текста (списки ради списков)
- Идентичные формулировки на разных сайтах (даже перефразированные)
- Главная меньше 3000 слов
- Меньше 12 H2-секций на главной
- Меньше 15 заглушек изображений на главной

### Обязательно

- **Тон** — 3-е лицо платформы + прямое обращение «вы» к читателю: «{brand} предлагает...», «Вы можете легко пополнить счёт через...»
- **Энциклопедическая глубина**: каждая H2 — отдельная тема с 200-350 словами и 1-2 изображениями
- **Сводная таблица параметров** в Hero (или сразу после Hero) с эмодзи-маркерами: ✅ Сайт, 📃 Лицензия, 🎮 Игры казино, 🃏 Live Casino, 🎲 Live-игры, 🎰 Число игр, 🔢 RTP, 🎁 Бонусы, 💳 Депозит, 💰 Вывод, ⌛ Скорость, 📱 Приложение, 📞 Поддержка
- **Таблица VIP-уровней или таблица бонусов на 4 депозита** — обязательна где-то на главной
- **Повторяющийся промо-баннер** после каждых 2-3 секций (5-7 раз на главной)
- **Numbered list** для пошаговых инструкций (регистрация, депозит, вывод, активация промокода) — 4-7 шагов на инструкцию
- **Bullet list** для способов оплаты, преимуществ, security features
- **FAQ** в конце с 4-6 вопросами, развёрнутые ответы 3-6 предложений каждый
- **Финальный блок** с рейтингом 4.9/5 и итоговой кнопкой
- **Местные реалии региона**: Kaspi/Halyk/Jusan для KZ, конкретные банки для других регионов (см. `docs/REGIONS.md`)
- **Конкретные цифры (фактологические)**: «минимальный депозит 1 000 тенге», «обработка 1-5 минут», «бонус до 200 000 ₸»
- **Уникальные CTA-кнопки**: ни одна кнопка вне промо-баннера не должна повторять текст другой
- **Перемежение длинных и коротких предложений** для burstiness (5-30 слов)
- **Дозированные опечатки**: 1-3 орфографических + 1-2 тонких пунктуационных «ошибок» внутри текста на страницу (НЕ в H1/title/description, НЕ в первом предложении абзаца)

### Техники антидетекта AI-текста (для формата H)

1. **Burstiness** — чередовать длинные секции (250-350 слов) с короткими (80-120 слов) и средними (150-220 слов)
2. **Perplexity** — использовать неожиданные сравнения и точные технические детали («сеть TRC20», «волатильность слота», «маржа на топ-события 4-5%»)
3. **Региональные маркеры** — упоминания банков, провайдеров, городов, лиг из `docs/REGIONS.md` встроены в энциклопедический текст (не в личных историях)
4. **Контекстные детали** — конкретные суммы, проценты, названия игр, номера версий, время обработки
5. **Структурное чередование** — внутри H2: абзац → numbered list → абзац → таблица → абзац → bullet list. Никогда 4 абзаца подряд
6. **Человеческие опечатки (дозированно)** — 1-3 орфографические + 1-2 пунктуационные ВНУТРИ текста на страницу. Запрещено: запятые на краях абзацев, абзацы без точки, ошибки в SEO-критичных местах. Подробности в `docs/CONTENT_GUIDE.md` (техника 6)
7. **Непоследовательность форматирования** — числа то цифрами то словами в разных местах, «{brand}» / «{брендкириллица}» вперемешку
8. **Энциклопедические переходы** — «Помимо стандартных возможностей», «Стоит обратить внимание на», «Одной из ключевых особенностей является», «Среди других возможностей»
9. **Развёрнутые FAQ** — 3-6 предложений каждый, с конкретными цифрами и пошаговыми указаниями
10. **Неравномерная глубина** — 3-4 секции подробные, 5-6 средние, 2-3 короткие (см. CONTENT_GUIDE.md техника 10)

### Пример правильного текста (формат H)

> «{brand} Casino — это популярная онлайн-платформа, которая предлагает широкий выбор игр казино, включая слоты, настольные игры и live-дилеров. Одна из ключевых особенностей платформы — поддержка криптовалют наряду с локальными методами оплаты. Игроки из Казахстана могут пополнить счёт через Kaspi или Halyk Bank, а также использовать USDT по сети TRC20 — транзакции обычно обрабатываются за 15-30 минут.»

### Пример неправильного текста

> «Пополнение осуществляется мгновенно. Вывод средств занимает от 1 до 3 рабочих дней. Минимальный депозит составляет 1 000 тенге. Платформа предоставляет широкий спектр платёжных методов.»

(Сухо, без подробностей, без местных банков, без структуры — AI-детектор ловит мгновенно.)

### Генерация контента — важные правила для агента

1. Для каждого проекта генерировать тексты **с нуля**, не переиспользовать фразы из предыдущих проектов
2. **Структура секций главной фиксированная** (см. `docs/VARIATION_STRATEGY.md`, секция 12, формат H) — но формулировки H2-заголовков и текстов уникальны для каждого проекта
3. **Промо-баннер повторяется 5-7 раз** с одинаковой структурой, но **разными заголовками** («Зарегистрируйтесь сегодня...», «Сделайте первый депозит за 7 минут...», «Активируйте промокод и удвойте...»)
4. Менять **набор упоминаемых способов оплаты**: один сайт делает акцент на Kaspi и Halyk, другой — на криптовалютах, третий — на международных методах
5. **FAQ-вопросы и ответы** полностью уникальны на каждом сайте — другие формулировки, другие темы (FAQ-банк в `docs/FAQ_BANK.md`)
6. **Региональные данные** берутся из `docs/REGIONS.md` по полю `region` в конфиге

### ⚠️ Внешние ссылки — всегда `#` до получения реальных URL

При создании сайта **ВСЕ ссылки, ведущие за пределы домена проекта, проставляются как `"#"`** (заглушка). Реальные URL подставляются позднее, на этапе деплоя, когда от партнёрской программы получены проверенные ссылки с метками.

**Что это касается:**

- `affiliate_url` в `project.config.json` — `"#"`
- Все CTA-кнопки в шапке, футере, hero, промо-баннерах, финальных блоках, FAQ-секциях — `href="#"`
- Все ссылки «Скачать APK», «Перейти на сайт», «Регистрация» вне внутренних страниц проекта — `"#"`
- Ссылки на соцсети партнёра, на их Telegram-канал, на TestFlight — `"#"`
- Любая внешняя URL вида `https://*.com/...` за пределами домена сайта — `"#"`

**Что НЕ касается** (внутренние ссылки оставляем как есть):

- Ссылки на собственные страницы сайта: `/registraciya`, `/bonus`, `/about` и т.п.
- `<link rel="canonical">` со собственным доменом
- `<meta property="og:url">` со собственным доменом
- Изображения, шрифты, ассеты с CDN (Google Fonts, OG-image)
- Schema.org-разметка (URL сайта в `Organization`, `WebSite`, `Article`)

**Структура кода должна оставаться готовой к замене.** Все CTA-кнопки сохраняют атрибуты `external` (или `target="_blank" rel="noopener noreferrer sponsored"`) — чтобы при подстановке реального URL не нужно было перерисовывать компоненты, только заменить значение переменной.

**Паттерн в коде:**

```astro
---
const affiliateLink = '#'; // TODO: заменить на реальный URL партнёрки при деплое
---
<CTAButton href={affiliateLink} external size="lg">Играть сейчас</CTAButton>
```

**При деплое — финальная подмена одной командой:**

```bash
cd projects/{brand}/project_N_*
grep -rl "'#'" src/ project.config.json | xargs sed -i '' "s|'#'|'https://реальный-партнёрский-url.com/...'|g"
npm run build
```

Это гарантирует: на этапе разработки и тестирования сайт работает «вхолостую» (никто не сливается на пустую партнёрку), а при деплое одной командой все ссылки становятся рабочими.

## 7. E-E-A-T (Experience, Expertise, Authoritativeness, Trustworthiness) — формат H

В формате H **персона-автор не используется** (мы не личный блог). Вместо этого E-E-A-T обеспечивается через:

### Метаинформация публикации

| Поле             | Источник                                             | Пример                          |
| ---------------- | ---------------------------------------------------- | ------------------------------- |
| `datePublished`  | Генерируется при создании проекта (1-3 месяца назад) | 2026-01-15                      |
| `dateModified`   | Текущая дата (или -7…-30 дней)                       | 2026-04-26                      |
| `publisher.name` | Имя сайта (по домену)                                | «BC.Game Brazil», «1xBet Обзор» |
| `editor`         | Условное название редакции                           | «Команда обзоров», «Редакция»   |
| Время чтения     | Рассчитывается автоматически из объёма текста        | «8 минут»                       |

### Компонент ArticleMeta (формат H)

На каждой подстранице — блок с:

- Дата публикации (формат: «15 января 2026»)
- Дата обновления (отличается от публикации на 7-30 дней)
- Время чтения (рассчитывается автоматически)

**Имя конкретного автора не выводится** — это обзор от редакции/платформы, а не личный блог.

### Страница /about — обязательные секции (формат H)

1. **О платформе** — описание {brand}, год основания, основные направления (казино / спорт / live)
2. **Лицензии и регулирование** — указание лицензии (Curaçao / MGA / Anjouan и т.п.), номер, юрисдикция
3. **Как мы готовим обзоры** — методология: проверяем функциональность, тестируем способы оплаты, изучаем условия бонусов
4. **Про партнёрку** — честное упоминание партнёрских ссылок и того, как это влияет/не влияет на обзоры
5. **Обновление информации** — как часто обновляется сайт, что меняется
6. **Ответственная игра** — 21+, возрастные ограничения, ссылки на сервисы помощи

### Schema.org для подстраниц (формат H)

```json
{
	"@type": "Article",
	"headline": "{{title}}",
	"datePublished": "{{datePublished}}",
	"dateModified": "{{dateModified}}",
	"publisher": {
		"@type": "Organization",
		"name": "{{site.name}}",
		"url": "https://{{domain}}/"
	},
	"mainEntityOfPage": "https://{{domain}}{{path}}"
}
```

(Поле `author` через `Person` не используется — у нас нет персоны автора. Если SEO-валидатор требует author, использовать `Organization` со ссылкой на /about.)

## 8. Изображения → заглушки с описаниями

### Подход

Реальные растровые изображения НЕ генерируются и НЕ используются. Вместо каждого места, где могла бы быть картинка, вставляется **HTML/CSS-заглушка** — стилизованный блок с описанием того, что должно быть на картинке.

Это позволяет:

- Мгновенно генерировать проекты без ожидания AI-генерации
- Легко заменить заглушки на реальные изображения позже
- Не хранить тяжёлые PNG/WebP файлы

### Что НЕ является изображением (делать всегда качественно)

- **SVG-иконки** — inline SVG с осмысленными путями, тематические, качественные
- **CSS-градиенты и паттерны** — фоны секций, декоративные элементы
- **Emoji и Unicode-символы** — в заголовках, карточках
- **Аватар автора** — CSS-инициалы в цветном блоке (не картинка)

Это всё — ответственность агента. Они всегда должны быть качественными и тематическими.

### Обязательный компонент ImagePlaceholder.astro

Каждый проект ОБЯЗАН иметь компонент `src/components/ui/ImagePlaceholder.astro` (код в REFERENCE_ARCHITECTURE.md).

Использование — ВМЕСТО ЛЮБОГО `<img>`:

```astro
import ImagePlaceholder from '../components/ui/ImagePlaceholder.astro';

<ImagePlaceholder description="1. Казино: фишки, карты и рулетка на тёмном фоне" />
<ImagePlaceholder description="2. Слот Sugar Rush: конфеты и яркие цвета" aspect="16/10" />
```

**Нумерация описаний**: каждая заглушка на странице получает порядковый номер с точкой в начале описания (`1. ...`, `2. ...`, `3. ...`). Нумерация сквозная в пределах одной страницы, начинается с 1.

**ЗАПРЕЩЕНО:**

- `<img src="...">` — НЕЛЬЗЯ нигде
- `<Image>` из astro:assets — НЕЛЬЗЯ
- Заглушка без описания — НЕЛЬЗЯ
- Описание без порядкового номера — НЕЛЬЗЯ
- Описание «картинка» / «изображение» — НЕЛЬЗЯ (конкретное описание на русском)

## 13. Хостинг и серверная оптимизация (Apache)

### `.htaccess` — обязательные блоки

#### Редиректы — НЕ нужны в `.htaccess`

Все редиректы (HTTPS, www/без-www, trailing slash) настраиваются на уровне хоста. В `.htaccess` их добавлять **НЕ нужно**:

- ~~HTTPS принудительно~~ — делается на хосте
- ~~Без www~~ — делается на хосте
- ~~Убрать trailing slash~~ — делается на хосте

#### Безопасность (Security headers)

| Заголовок                   | Значение                                       | Зачем                       |
| --------------------------- | ---------------------------------------------- | --------------------------- |
| `X-Content-Type-Options`    | `nosniff`                                      | Запрет MIME-sniffing        |
| `X-Frame-Options`           | `SAMEORIGIN`                                   | Защита от clickjacking      |
| `X-XSS-Protection`          | `1; mode=block`                                | Защита от XSS (legacy)      |
| `Referrer-Policy`           | `strict-origin-when-cross-origin`              | Контроль referer            |
| `Permissions-Policy`        | `camera=(), microphone=(), geolocation=()`     | Отключение ненужных API     |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains; preload` | HSTS — принудительный HTTPS |

#### GZIP-сжатие (`mod_deflate`)

Сжимаемые типы:

- `text/html`, `text/css`, `text/javascript`, `text/xml`, `text/plain`
- `application/javascript`, `application/json`, `application/xml`
- `image/svg+xml`
- `font/woff2`, `font/woff`, `font/ttf`

#### Кеширование (`mod_expires` + `Cache-Control`)

| Тип файлов                              | Срок кеша | Cache-Control               | Почему                       |
| --------------------------------------- | --------- | --------------------------- | ---------------------------- |
| HTML                                    | 0 секунд  | `no-cache, must-revalidate` | Контент меняется             |
| CSS, JS                                 | 1 год     | `public, immutable`         | Astro добавляет хеши в имена |
| Изображения (WebP, AVIF, JPG, PNG, SVG) | 1 год     | `public, immutable`         | Статические ассеты           |
| Шрифты (woff2, woff, ttf)               | 1 год     | `public, immutable`         | Статические ассеты           |
| JSON, XML                               | 0 секунд  | —                           | Динамические данные          |

#### ETag

- **Отключить** — избыточен при наличии Expires и Cache-Control

#### MIME-типы (`mod_mime`)

Явно задать для: `.webp`, `.avif`, `.woff2`, `.woff`, `.ttf`, `.js`, `.css`

#### Прочее

- **Скрытие файлов** — блокировка доступа к файлам, начинающимся с `.`
- **Листинг директорий** — отключён (`Options -Indexes`)
- **Кастомные ошибки** — `ErrorDocument 404 /404.html`

### Индексация — включена по умолчанию

Все новые проекты создаются сразу открытыми для индексации:

1. **`public/robots.txt`** — `Allow: /` + ссылка на `sitemap-index.xml`
2. **`SEOHead.astro`** — дефолт `noindex = false`, что рендерит `<meta name="robots" content="index, follow, max-snippet:-1, max-image-preview:large, max-video-preview:-1">`
3. **`project.config.json`** — `"noindex": false`
4. **`src/pages/404.astro`** — единственное исключение: явный `noindex={true}` остаётся (так и должно быть для 404).

#### Если нужно временно закрыть проект от индексации

- [ ] `public/robots.txt` — заменить `Allow: /` на `Disallow: /`
- [ ] `project.config.json` — `"noindex": true`
- [ ] В `BaseLayout`/страницах передавать `noindex={true}` (или поменять дефолт в `SEOHead.astro`)
- [ ] Пересобрать проект (`npm run build`)
